개요

  • 지출과 구독 서비스를 한곳에서 관리하는 웹서비스이고, 7인 팀에서 PM과 최종 발표를 맡았습니다.
  • 회원가입·로그인 모달·약관 동의·비밀번호 재설정과 커뮤니티 기능을 맡았습니다. DB 설계와 문서 작업은 팀원이 했고, 저는 팀원 기능과 DB 연동이 실제로 동작하는지 최종 검토하며 오류 위치를 찾았습니다. 수정 코드는 ChatGPT로 작성해 적용했습니다.
  • 마감 직전에는 팀원 기능의 오류를 맡아, 저장할 때와 조회할 때 쓰는 사용자 기준이 달랐던 문제를 하루 안에 고쳤습니다.

메인부터 약관 동의·회원가입, 비밀번호 찾기, 로그인, 메뉴의 화면들, 관리자 로그인까지 눌러 본 녹화입니다. 녹화하려고 넣은 시연 데이터를 썼고, DB는 팀에서 쓴 Oracle 대신 Oracle 호환 모드의 MariaDB에서 돌렸습니다.

배경과 문제

복잡한 소비와 구독 내역을 한곳에서 정리하자는 주제로, K-Digital Training 단기 과정에서 7명이 만든 웹서비스입니다. 지출 기록, OTT 구독 공유, 연령대별 게시판, AI 멘토를 한 사이트에 묶었습니다.

마감 직전, 개발 담당이었던 조장과 PM인 제 계정에서는 저장되던 지출·저축·목표가 다른 팀원 계정에서는 대시보드에 나오지 않았습니다. 기능은 다른 팀원이 만든 것이었습니다.

상황

지출 등록·저축 등록·목표 설정이 개발 담당이었던 조장과 PM인 제 계정에서는 저장되고 차트에도 나왔는데, 다른 팀원들이 각자 계정으로 하면 대시보드에 나오지 않았습니다.

AI에 준 조건
  • "보내주는 파일들 자세하게 분석하고 왜 안되는지 확인해보고 알려줘. 확인이 필요한 파일이 있으면 바로 말해줘"
  • AI가 첫 답에서 수정 코드를 줬지만 적용하지 않고, "요구한 파일 먼저 보내주고 최종적으로 어떤 문제인지 확인하고 그거에 맞게 수정할게"라고 순서를 정함
AI의 답과 이어진 작업

AI는 처음에 원인 후보 다섯 가지(프론트가 보내는 userId, 샘플 데이터의 USER_ID=1, 화면에 박힌 카테고리 번호, 외래키, 목표 저장 컨트롤러 누락)를 표로 정리하고 파일을 더 요청했습니다. 파일을 다 받은 뒤에는 dashboard.js 369·642·818줄의 userId: 1 하드코딩으로 확정했습니다. 저장은 늘 1번 사용자로, 조회는 로그인한 사용자 기준으로 하고 있었던 겁니다.

직접 확인한 것
  • 다른 아이디로 로그인해 재현 → 지출·저축은 해결, 목표 등록은 여전히 실패
  • 콘솔 오류 Uncaught ReferenceError: userId is not defined (dashboard.js:839)를 그대로 붙여 다시 질문 → AI는 const userId = 1만 지워 요청 본문에 변수가 남은 것이라고 짚고, 1로 되돌리지 말고 서버가 세션에서 사용자를 꺼내도록 고치라고 답함

대시보드와 마이페이지가 서로 다른 목표 달성률

상황

마이페이지의 개인 소비 목표 게이지가 0%에서 움직이지 않았습니다.

AI에 준 조건
  • 대시보드 목표 카드와 같은 디자인·동작으로 바꾸고, 고정 목표 1개와 일반 목표 2개를 어떻게 보여 줄지 질문
  • "3개 파일을 먼저 수정하고 다음에 MyPageService.java를 수정해보자", 고칠 순서를 정함
  • "MyPageService.java를 수정하게 된다면 어떤걸 수정하면 되는거야?", 바꿀 범위를 먼저 확인
AI의 답과 이어진 작업

AI는 대시보드는 EXPENSES 테이블의 저축 합계로, 마이페이지는 SAVING_GOALS.savedAmount(기본값 0)로 달성률을 계산하고 있어 기준이 다르다고 설명했습니다. MyPageService에 ExpenseRepository를 넣어 같은 저축 합계로 계산하게 바꿨습니다.

직접 확인한 것
  • 마지막에 "지금까지의 내용이 어떤 이유로 문제가 있던건지 정리해줘"로 원인을 정리해 트러블슈팅 문서에 수정 전·후 코드를 붙임

AI가 원인을 잘못 짚었던 햄버거 메뉴

상황

마이페이지의 햄버거 메뉴 디자인이 메인 페이지와 달랐습니다. AI는 처음에 클릭이 안 되는 문제로 보고 JavaScript 코드를 줬습니다.

AI에 준 조건
  • 받은 코드는 적용하지 않고, 메인과 마이페이지 화면을 캡처해 나란히 보냄
  • "mypage.css를 수정해도 sidebar.jspf 파일을 가져오는 거라 적용이 안 되는 것 같다"는 내 추측을 같이 전달
AI의 답과 이어진 작업

AI는 앞에서 준 코드는 적용하지 않는 게 맞다고 정정했습니다. 원인은 공통 사이드바 뒤로 마이페이지 전용 사이드바가 겹쳐 보이는 것이었고, mypage.css만 고치면 됐습니다.

직접 확인한 것
  • 수정 후 두 화면을 다시 확인하고("이제 잘 적용돼") 다음 문제로 넘어감

화면은 SPICY, 서버는 HOT

같은 대화 · 2026.06.10

상황

AI 멘토 성향이 서버에는 MILD·MEDIUM·HOT으로 정해져 있는데, 마이페이지 선택지는 SPICY였습니다. 그대로 두면 매운맛을 골라도 멘토가 바뀌지 않을 상황이었습니다.

AI에 준 조건
  • 값이 어긋난 걸 먼저 찾아서 SPICY를 HOT으로 바꿔 달라고 요청
  • editprofile.jsp는 직접 고친 뒤 "다른 파일은 너가 확인이 필요할 것 같아"로 나머지 확인을 맡김
AI의 답과 이어진 작업

AI는 화면 값만 바꿔서는 부족하고, MyPageService.updateProfile()이 mentorTone을 아예 저장하지 않고 있다는 것을 찾아 저장 코드를 넣었습니다.

직접 확인한 것
  • 수정 후 다시 실행해 동작을 확인("이제 작동이 잘돼")
결과
