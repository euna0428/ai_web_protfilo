개요

  • 여행지를 찾고 일정·경로를 짜고 후기까지 남기는 여행 플래너 웹서비스이고, 개발 중반부터 팀장을 맡았습니다.
  • 메인, 로그인·회원가입, 비밀번호 찾기, 후기 커뮤니티, 고객센터, 관리자, 마이페이지 일부의 JSP 화면과 컨트롤러를 만들었고, 8만 자 분량 코드에서 중복된 DB 처리 코드를 줄였습니다.
  • 4명이 따로 만든 기능을 2026년 2월 25일부터 3월 1일까지 세 차례에 걸쳐 하나로 합쳤습니다.

메인 카드와 카테고리 버튼, 비회원 찜 안내, 회원가입·로그인, 마이페이지, 후기, 고객센터, 관리자 화면까지 눌러 본 녹화입니다. 카드에 [시연]이 붙은 여행지는 녹화하려고 넣은 예시 데이터라 카테고리가 실제와 다를 수 있고, 지도 영역은 녹화 환경에서 Kakao 지도가 열리지 않아 비어 있습니다.

배경과 문제

여행지 찾기, 일정·경로 짜기, 후기 남기기를 한 서비스 안에서 하도록 만든 여행 플래너입니다. K-Digital Training 장기 과정 4인 팀 프로젝트였습니다.

4명이 각자 PC에서 만든 기능을 하나로 합쳐야 했습니다. 개발 중반에 팀장을 맡았을 때는 합칠 때마다 Long·Integer 타입 불일치, URL 경로 충돌, 팀원별 DB 설정 차이로 화면이 열리지 않는 일이 반복되고 있었습니다.

개발 중반부터 팀장(PM) · UI/UX 총괄 · 담당 화면과 서버 기능 개발 · 중복 DB 처리 코드 정리 · 팀원 기능·DB 연동 최종 검토와 통합

상황

팀원 4명이 각자 PC에서 만든 코드를 받아 main 브랜치에 직접 합쳤습니다. 2월 25일 첫 병합은 결과를 잃어 다시 시작했고(커밋 "병합 날려서 다시 작업 들어감"), 합칠 때마다 Long·Integer 데이터 타입 불일치, URL 경로 충돌, 화면 접근 오류가 반복됐습니다.

AI에 준 조건
  • 오류를 타입 불일치, 경로 충돌, 화면 접근 문제로 나눠서 질문
  • 관련 파일의 호출 관계와, 고친 코드가 다른 화면에 미치는 영향을 같이 설명하게 함
  • 팀원별 MySQL 연결 설정 차이, Spring Security·WebFlux 구성도 함께 점검
AI의 답과 이어진 작업

유형별로 공통 처리 기준을 정해 같은 방식으로 고쳤습니다. 외부 API 호출 구조는 WebFlux 의존성이 충돌하지 않도록 WebClient에서 RestClient로 바꿨습니다.

직접 확인한 것
  • 2월 26일 헤더·푸터 공통화와 plans 병합 → 2월 27일 2차(병훈님·호영님 작업) → 3월 1일 3차 병합 완료
  • 3월 3일·5일에 페이지 연결, 구글 로그인, 관리자 화면, 로컬 접속 오류 화면까지 마무리
