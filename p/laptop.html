개요배경과 문제역할과 기여기술적 의사결정성과와 배운 점

개요

  • 학과·예산·운영체제·우선순위를 고르면 맞는 노트북 5개와 추천 이유를 보여 주는 웹서비스입니다.
  • 터미널에서만 돌던 Python 추천 프로그램을 FastAPI API 4개와 React 5단계 화면으로 옮겼습니다.
  • 옮기는 동안 점수 계산이 그대로인지 추천 규칙 7,227건을 돌려 확인했습니다.

첫 화면부터 5단계 입력, 추천 결과 카드 3장 뒤집기, 모델 검색 링크로 판매가 확인까지 녹화했습니다. 예산 200만 원으로 받은 1위 카드의 예상가는 150~230만 원이고, 링크로 연 다나와 판매가도 1,839,000원으로 예산 안에 들어옵니다. 마지막 다나와 화면은 2026년 11월 7일에 캡처한 검색 결과이고, 결과 카드의 노트북 그림은 실제 제품 사진이 아니라 자리 표시 이미지입니다.

배경과 문제

학과마다 필요한 노트북 사양이 다르다는 데서 출발했습니다. 학과·예산·운영체제·우선순위를 넣으면 맞는 노트북 5개와 추천 이유를 보여 줍니다.

처음에는 터미널에서만 돌아가는 Python 프로그램이었습니다. 웹으로 옮기면서 화면과 API 코드를 새로 받다 보면 점수 계산 함수까지 바뀔 위험이 있었습니다.

단독 개발 · 기획, 데이터 구축, 백엔드, 프론트엔드

  • 8개 학과 권장 사양과 노트북 45종을 CSV로 정리하고 점수 규칙을 설계
  • FastAPI API 4개와 Pydantic 입력 검사
  • React 5단계 입력 화면과 결과 화면

상황

터미널 프로그램(recommend_laptop.py)을 웹 API로 감싸야 했습니다. 화면과 API를 붙이는 코드를 받다 보면 점수 함수까지 새로 짜인 코드가 섞여 들어올 수 있었습니다.

AI에 준 조건
  • "기존 점수 계산은 변경하지 않는다"를 질문 맨 앞에 조건으로 적음
  • 추천 함수는 그대로 두고 요청 처리(FastAPI)와 입력 화면(React)만 나누는 구조를 질문
AI의 답과 이어진 작업

추천 로직은 recommender.py에 그대로 두고, main.py는 요청값 검사와 응답만 맡는 구조로 나눴습니다. 받은 코드는 기존 함수와 비교해 필요한 부분만 적용했습니다.

직접 확인한 것
  • CLI와 웹 백엔드가 읽는 CSV 위치가 달라, 실제 데이터 경로와 컬럼 연결을 하나씩 대조
  • /api/health, /api/departments, /api/laptops, /api/recommend를 직접 호출해 정상 응답과 404·422 오류 응답 확인
  • 학과·예산·우선순위·운영체제 조합으로 추천 규칙 7,227건을 돌려 결과 확인
결과

점수 계산은 바뀌지 않았고, 없는 학과는 404, 형식이 틀린 값은 422로 돌아갑니다. 반복 요청 때 CSV를 다시 읽지 않도록 lru_cache(maxsize=1)를 붙였습니다.

def departments() -> dict[str, list[dict]]:
    df = load_departments()
    return {"departments": [department_to_dict(row, idx) for idx, row in df.iterrows()]}


@app.get("/api/laptops")
def laptops() -> dict[str, list[dict]]:
    df = load_laptops()
    return {"laptops": [laptop_to_dict(row) for _, row in df.iterrows()]}

def create_recommendation(request: RecommendRequest) -> dict:
    try:
        return recommend(request.model_dump())
    except ValueError as exc:
        raise HTTPException(status_code=404, detail=str(exc)) from exc

성과와 배운 점

  • 5단계 입력 화면

웹 전환에서 AI에게 "웹으로 바꿔 달라"고만 했다면 화면에 맞춰 점수 계산까지 새로 짜인 코드를 받았을 겁니다. 바꾸면 안 되는 것을 먼저 적고, 받은 결과는 API를 직접 호출해 확인하니 점수는 그대로였습니다.

그 뒤로는 원하는 결과보다 바꾸면 안 되는 조건을 먼저 적고 시작합니다. 지출메이트에서 팀원 기능을 고칠 때도 기존 기능은 건드리지 않고 필요한 부분만 바꾼다는 조건부터 걸고 수정했습니다.
