  • 목적지를 검색하면 가는 길과 목적지 주변의 위험구간을 골라, 다가갈 때와 들어설 때 두 번 음성으로 알려 줍니다.
  • 날씨와 돌발상황 API를 받아 위험도와 지도 데이터를 다시 계산하는 파이프라인도 만들었습니다.

현재 위치에서 출발해 목적지를 검색하고, 시연 주행으로 경로를 따라가며 위험구간에 다가갈 때와 들어설 때 음성 경고가 나오는 장면입니다. 소리 켜기 버튼을 누르면 경고 음성이 들립니다.

배경과 문제

사고 다발 지역 안내는 내비게이션에도 있습니다. 여기에 날씨와 돌발상황을 반영한 위험도를 더하고, 검색한 경로 위의 위험구간만 골라 알려 주도록 범위를 정했습니다.

백석대학교로 경로를 잡으면 위험구간이 0개로 나왔습니다. 학교 주변 사거리는 사고가 잦은 곳이라, 기능 오류인지 데이터 문제인지부터 가려야 했습니다.

상황

발표 자료를 만들기 전에, 위험구간에 다가갈 때 한 번, 들어설 때 한 번 경고하는 구조가 실제 코드에 있는지 확인이 필요했습니다.

AI에 준 조건
  • "다가오기 전 1번, 진입 시 1번 총 2단계 경고인가?"를 먼저 확인
  • 2단계 경고, 멀어지면 경고 상태 초기화, 경로 자동 재탐색을 요청
  • 내 위치 기준 위험구간 20개와 검색한 경로의 위험구간은 목적이 다르니 분리하라고 요구
  • "현재 내가 등록한 API로 가능한 부분만 개발하고, 아니면 개발 안 하는 걸로" 범위를 정함
AI의 답과 이어진 작업

AI는 먼저 지금 코드는 반경 안에 들어올 때 한 번만 경고하는 구조라서 "2단계 경고"라고 발표하면 과장이라고 짚었습니다. 이어서 추가 API 없이 접근(1차)·진입(2차) 경고를 나누고, 멀어지면 해당 구간의 경고 상태를 지우고, 경로에서 벗어나면 현재 위치 기준으로 경로를 다시 분석하도록 risk_map.js와 navigation_server.py를 고쳤습니다. 상용 내비게이션의 턴바이턴 안내는 아니라는 한계도 같이 적어 줬습니다.

직접 확인한 것
  • 고친 파일을 적용한 뒤 직접 실행해 경고 문구와 음성이 단계별로 다르게 나오는지 확인
  • 다른 방향으로 가면 재탐색이 되는지 다시 질문해 조건(경로 160m 이탈, 출발점 220m 이동, 45초 간격)을 확인

function showRouteAlert(item, phase) {
    const zoneId = item.zone_id || item.location_name;
    if (!zoneId) return;
    const prevPhase = routeAlertStateByZone.get(zoneId);
    if (prevPhase === phase || (prevPhase === "entry" && phase === "approach")) return;

    routeAlertStateByZone.set(zoneId, phase);
    const gradeColor = colorByGrade[item.grade] || "#ef4444";
    const title = phase === "entry" ? `${item.grade} 위험구간 진입` : `${item.grade} 위험구간 접근`;
    const message = phase === "entry"
        ? `${item.grade} 위험구간에 진입했습니다. 감속하고 주변 차량과 보행자를 주의해 주세요.`
        : `${item.grade} 위험구간 ${Math.round(item.distance_m)}미터 전방입니다. 감속하고 전방을 주의해 주세요.`;

    setMapMessage(`<div class="auto-risk-alert" style="--alert-color:${gradeColor};"><strong>${escapeHtml(title)}</strong><span>${escapeHtml(item.location_name)} · ${formatDistance(item.distance_m)}</span></div>`);
    const voiceKey = `${zoneId}-${phase}`;
    if (voiceKey !== lastVoiceAlertKey) {
        lastVoiceAlertKey = voiceKey;
        speakMessage(message);
    }
}

function checkNavigationAlerts(lat, lon) {
    if (!activeRouteRiskItems.length) return;
    clearRouteAlertStates(lat, lon);
    const riskTarget = getRouteAlertCandidate(lat, lon);
    if (!riskTarget) return;
    const phase = riskTarget.distance_m <= riskTarget.alert_radius_m ? "entry" : "approach";
    showRouteAlert(riskTarget, phase);
}

function shouldAutoReroute(lat, lon) {
    if (!selectedDestination || !activeRoutePathPoints.length || routeAnalyzeInProgress) return false;
    const now = Date.now();
    if (now - lastAutoRerouteAt < ROUTE_REROUTE_COOLDOWN_MS) return false;

    const distanceFromRoute = minDistanceToRouteMeters(lat, lon, activeRoutePathPoints);
    if (distanceFromRoute >= ROUTE_DEVIATION_REROUTE_M) return true;

    if (!lastRouteOriginPosition) return false;
    const movedFromOrigin = haversineDistanceMeters(lat, lon, lastRouteOriginPosition.lat, lastRouteOriginPosition.lon);
    return movedFromOrigin >= ROUTE_DEPARTURE_MOVE_REROUTE_M;
}

function maybeAutoReroute(lat, lon) {
    if (!shouldAutoReroute(lat, lon)) return;
    lastAutoRerouteAt = Date.now();
    analyzeRouteRisk({ skipSearch: true, autoReroute: true, keepMessage: true });
}

백석대 가는 길에만 위험구간이 0개

같은 대화 · 2026.05.29

상황

김천역으로 경로를 잡으면 위험구간 13개가 뜨는데, 백석대학교로 잡으면 0개였습니다. 학교 주변 상명대 사거리와 단국대 사거리는 사고가 잦은 곳이라 이상했습니다.

AI에 준 조건
  • "교통사고 데이터가 다 들어간 게 맞는지" 실행 화면을 붙여 질문
  • "내 목표는 일부만 있는 게 아니라 전체를 보는 거야", 전체 데이터셋으로 CSV·그래프를 다시 만들라고 요구
  • 상명대·단국대 사거리가 왜 없는지, 공공데이터에서 더 받아야 하는 파일이 있는지 질문
AI의 답과 이어진 작업

AI는 API 오류가 아니라 데이터 범위와 경로 매칭 기준(경로선 300m) 문제라고 봤습니다. 위험구간 12,756개 중 백석대·안서동 이름이 붙은 곳은 0개였습니다. 그래서 경로 매칭을 500m로 넓히고 목적지 반경 1.5km를 따로 조회하게 나눴습니다. 이어서 지금 데이터는 보행노인 5,991·자전거 5,046·보행어린이 1,212·스쿨존어린이 531건처럼 특정 유형의 사고다발지역뿐이라, 일반 교통사고를 보려면 지자체별·법규위반별 사고다발지역 API가 필요하다고 답했습니다.

직접 확인한 것
  • 공공데이터포털에서 두 API를 직접 활용 신청하고 인증키를 발급
  • AI가 만든 수집 코드는 AI 환경에서 실제 호출 검증을 못 했다고 해서, 내 PC에서 main.py를 실행해 데이터를 받음
  • 키는 .env에만 두고 저장소에는 올리지 않음

백석대 경로가 0개로 나온 걸 직접 돌려 보지 않았다면 위험구간 표시 기능은 정상이라고 넘겼을 겁니다. 김천역과 백석대를 같은 조건으로 실행해 비교하고 나서야 기능이 아니라 데이터 범위의 문제라는 게 드러났습니다.
