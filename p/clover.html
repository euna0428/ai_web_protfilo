Android Studio 에뮬레이터에서 실행한 화면입니다. 앱 화면은 코드에 넣어 둔 값으로 동작해서 아무 값이나 입력해도 로그인되고, 서버와 실제로 연결되는지는 확인하지 못했습니다. 최종 발표에서도 앱 화면은 시연하지 않았습니다. 장면 목록에 ‘담당’이 붙은 화면이 제가 만든 부분입니다.

배경과 문제

범용 중고거래 앱에는 옷의 사이즈와 핏 정보가 부족하다는 문제에서 출발한 의류 중고거래 Android 앱입니다.

조장으로 처음 PR 병합을 맡았는데, 첫 PR부터 파일 4개에서 충돌이 났습니다. 실제 휴대폰에 연결하면 체형 분석 대신 다시 로그인하라는 화면으로 넘어가는 문제도 있었습니다.

처음 맡은 PR 병합, 충돌 파일 4개

ChatGPT 대화 「Merge vs Rebase 선택」 2026.06.01

상황

PR #12(feat/frontend/login)를 develop과 합치는데 build.gradle.kts, CloverNavHost.kt, Color.kt, MainActivity.kt 네 파일에서 충돌이 났습니다. 병합을 처음 맡아서 어떤 버튼을 눌러야 하는지부터 몰랐습니다.

AI에 준 조건
  • "저기서 merge 누르면 병합하는 화면으로 나오는 건가?", 화면을 캡처해 단계마다 확인
  • AI가 정리해 준 build.gradle.kts 전체 코드를 받고 "아이콘 확장 부분은 왜 빠져 있는 거야?"라고 되물음
  • Color.kt는 "변수에서 많이 엇갈릴 것 같은데 그동안 했던 작업을 토대로 통일시켜야 할 것 같아"라고 방향을 정함
AI의 답과 이어진 작업

AI는 Rebase가 아니라 Merge를 고르고, gradle 파일은 왼쪽·오른쪽 중 하나를 고르지 말고 가운데에서 양쪽 의존성을 합치라고 했습니다. 공식 릴리스에 없는 lifecycle 2.7.7은 2.8.7로 바꿨습니다. 아이콘 확장 질문에는 주석을 지우면서 빠진 것처럼 보이게 만들었다고 인정하고, 병합할 때는 주석을 남기는 게 맞다고 고쳐 말했습니다. Color.kt는 한쪽을 버리지 않고 이름을 하나로 모은 뒤 예전 이름을 별칭으로 남겼습니다.

직접 확인한 것
  • material-icons-extended, coil-compose 2.6.0, navigation-compose 2.7.7 세 줄이 최종 코드에 들어갔는지 직접 대조
  • MainActivity는 임시 실행 코드를 버리고 navController 구조와 enableEdgeToEdge를 합친 결과로 적용

상황

에뮬레이터가 아니라 실제 휴대폰에 연결하면 체형 분석이 안 된다며 계속 다시 로그인하라는 화면으로 넘어갔습니다.

AI에 준 조건
  • "서버로 전송이 안 되는 건지, 로그인 토큰이 만료돼서 그런 건지" 두 가설을 같이 줌
  • AI 안대로 고쳤는데 같은 오류가 나자 "필요한 파일에 코드가 없어서 로직이 작동을 안 하는 건지도 확인이 필요해"라고 범위를 넓힘
  • AuthInterceptor.kt만 따로 보내 "이 파일만 확인해 줘"로 좁혀 질문
AI의 답과 이어진 작업

AI는 전송 코드, 토큰 전달, 결과 저장 흐름, 실기기 API 주소 순서로 나눠 봤습니다. 회원 ID(memberId)가 비어 있으면 서버에 보내기 전에 바로 다시 로그인 안내로 빠지는 구조였고, 토큰 재발급용 TokenAuthenticator는 파일만 있고 OkHttpClient에 등록돼 있지 않았습니다. 비어 있던 UseCase·Model 파일은 지금 화면이 쓰지 않아 직접 원인이 아니라고 구분했고, AuthInterceptor는 로직은 맞지만 로그가 없고 "Bearer Bearer"처럼 중복될 수 있다고 봤습니다. 같은 날 로그인 오류는 /api/members/me 응답의 필드 이름(id·memberId)이 앱과 다를 가능성으로 좁혔습니다.

직접 확인한 것
  • 체형 분석과 퍼스널 컬러 두 화면 모두 같은 지점(memberId == null)에서 멈추는지 확인

성과와 배운 점

  • 16PR 병합

  • 장려상교내 경진대회

병합 화면에서 AI가 정리해 준 gradle 전체 코드에 아이콘 확장 의존성이 빠진 것처럼 보였을 때, 그대로 적용했다면 다른 팀원의 화면이 빌드되지 않았을 겁니다. 원래 양쪽 코드와 줄 단위로 대조하고 나서야 빠진 게 없다는 걸 확인했습니다.

그래서 AI가 정리한 코드를 통째로 붙이기 전에 원래 코드와 대조하고, 어떤 파일을 어떤 순서로 고칠지부터 정합니다. 지출메이트 마이페이지 오류도 JavaScript·컨트롤러 3개 파일을 먼저, MyPageService를 그다음으로 정해 하나씩 확인하며 고쳤습니다.

아쉬운 점도 분명합니다. 앱 화면이 코드에 넣어 둔 값으로 돌아가는 상태에서 프로젝트가 끝나, 최종 발표에서 앱 화면을 시연하지 못했고 서버와의 실제 연결도 확인하지 못했습니다.
